CONFORMANCE — Auth0 needs ZERO claim overrides, unlike Entra
  code_challenge_methods_supported : ['S256','plain']   (Entra advertises none)
  token_endpoint_auth_methods      : client_secret_basic|post|private_key_jwt
  id_token_signing_alg             : RS256 present
  claims_supported                 : email AND email_verified NATIVE
The last line is the whole reason this was the easy path: core requires a true
`email_verified` for the require_email_verified floor and UNCONDITIONALLY for
bootstrap-owner promotion. Auth0 emits it; Entra needs xms_edov mapped in.

NOTE — core correctly refused a bootstrap arm
  The first migrate attempt also passed bootstrap_owner_email and got:
    409 "an active owner already exists; deactivate it before arming a
         bootstrap owner"
  That is the right guard. Promotion is therefore a separate admin act
  (promote_owner in lib.sh), which also works for issuers that never emit a
  true email_verified.

IDEMPOTENCE
  A second full run of auth0-idp-setup.sh reuses the app and detects that the
  active config already points at this issuer + client, then exits as a NO-OP.
  Verified: generation stayed at 3. Without that guard a re-run would MIGRATE,
  and a generation bump is a real event that invalidates sessions.
